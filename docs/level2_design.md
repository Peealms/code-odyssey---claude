## Goal
The player learns to **compare values** (`==` `!=` `<` `>` `<=` `>=`) and to **make decisions**
with `if`, `else` and `else if`. They also learn to spot the classic beginner bugs: `=` instead
of `==`, a `;` after `if (...)`, `else if`s in the wrong order, and Strings compared with `==`.
`&&`, `||`, `!`, nested ifs and `switch` wait for Level 3. About 15-20 minutes.

## The big idea: rules, not orders
In Level 1 every line is an **order**: type `fanOn = true;` and the fan starts. In Level 2 the
player writes **rules**: an `if` that a machine keeps following by itself.

```java
if (tide >= 4) {
    anchorUp = true;
}
```

- **Readings** are values the world changes by itself, like the `tide` rising and falling.
  A rule can check them, but nobody can set them: `tide = 5;` gets "You can't change the
  tide! You can only check it."
- **Machines** (the anchor, sea gates, sails, lanterns) run by themselves. Byte can't stand next
  to a gate flipping it every time the tide turns, so machines only take rules. If you type
  `gateOpen = true;`, Byte says "This gate runs by itself - give it a rule" and puts
  `if (___) { gateOpen = true; }` in the input. That isn't counted as a wrong try.
- A rule runs **when you type it, and again every time one of its readings changes**, the way
  game code checks its ifs over and over. There's one rule per room, and a new `if` replaces the
  old one. Rules stay after a respawn, like Level 1's variables. Machines keep following
  their room's rule after you leave the room (Level 1's gadgets only listen while you're in it).
- **Your own variables** still take orders: `hero = "Sarah";`, `hasSword = true;`. `hero` starts
  declared (you're already playing as someone), so switching is `hero = "...";` from the start.
  Level 1's `bridgeLength`, `jumpPower`, `fanOn` and `path` aren't used in this level.
- The **rule panel** in the HUD shows the room's rule on several lines, with live values:
  `if (tide >= 4)` turns into `3 >= 4` and then **false**. The branch that ran lights up, and any
  condition Java didn't need to check is greyed out. This is where players *see* how an if decides.

**Why every room needs its if.** Machines take no orders, readings keep changing while you
play, and every machine fails in a visible way when its rule is wrong: the ship runs aground,
the cave floods, the mast snaps. Byte then explains using the values at that moment ("The tide
was 2 when the anchor came up - the reef needs 4 or more."). The failure counts as a wrong try,
like Level 1's bridge that was too long. Rooms check what happens, not the text you typed, so
any correct rule works (`tide > 3` is as good as `tide >= 4`).

## Story and look
The team sails to Palm Tree Island to find Captain Clown Nose's treasure. Everything on the
island and the captain's ship runs on the captain's rules. The captain is a terrible programmer,
though, so the last room is full of bugs to fix. At the very end the captain guards the treasure
in person: Captain Clown Nose is the final boss.

- Rooms 0-2: **Palm Tree Island** (island terrain, palm trees, sand-coloured sky, clouds, water).
- Room 3: **the open sea**, on the team's small ship (the merchant ship art).

### Room 0 – The two doors (beach)
- Byte: "Crabs live here!" The level's first line is a Level 1 recap: `boolean hasSword = true;`.
- A wall-jump cliff (Chelzy) leads up to two doors, with the captain's rule carved above them:
  ```java
  if (key == 7) {
      rightDoorOpen = true;
  } else {
      leftDoorOpen = true;
  }
  ```
- `int key = 7;` makes `7 == 7` true, so the right door opens (the way on). There are coins behind
  both doors, and a crab guards the left one, so the player also tries another number:
  `key = 3;` runs the else and opens the left door. They see that exactly one branch runs.
- The doors only follow the captain's rule. If you type your own `if` here, Byte says "These
  doors follow the captain's rule - change key instead."
- Byte catches `key == 7;`: "== asks a question (is key 7?). To store 7 in key, use one =."
- Blanks / answer: `int key = _;` / `int key = 7;`

### Room 1 – The reef (lagoon)
- The tide (`tide`, 0-5) rises one step every 2 s and then falls back. A tide post shows it.
- The team's ship is anchored at the dock, with a reef across the lagoon. The sign says
  "THE REEF: TIDE 4 OR MORE".
- `if (tide >= 4) { anchorUp = true; }` waits for its moment. At tide 4 the anchor comes up, and
  the current carries the ship over the reef to the far dock.
- `if (tide >= 2)` lets the ship scrape the reef, and it gets towed back. Byte explains with the
  value, and it counts as a wrong try.
- The anchor only matters at the dock: once the ship is moving it finishes the trip, and it
  comes back by itself when nobody is aboard, so it can't leave you behind for good.
- Coins hang over the lagoon. April double-jumps from the deck to the high dock. Seashells on
  the docks spit pearls.
- Blanks / answer: `if (tide >= _) { anchorUp = ____; }` / `if (tide >= 4) { anchorUp = true; }`

### Room 2 – The tide locks (sea cave)
- Three dry chambers are joined by sea gates, and every gate follows the room's rule. At high
  tide (3 or more), the sea floods any chamber whose gate is open (deep water = back to the
  checkpoint).
- `if (tide >= 3) { gateOpen = false; } else { gateOpen = true; }` shuts the gates when the tide
  comes in, so you wait safely in a dry chamber, and opens them when it goes out, so you move on.
- The one-branch habit from Room 1 fails both ways, which is the point:
  `if (tide >= 3) { gateOpen = false; }` shuts the gates for good, and
  `if (tide < 3) { gateOpen = true; }` never shuts them, so the cave floods. Byte: "Your if only
  says what happens when the tide is high. Add an else for the rest of the time."
- Totem heads spit spikes across the chambers while you wait. Psalm shrinks under a barrel shelf
  between chambers 2 and 3.
- Blanks: `if (tide >= _) { gateOpen = _____; } else { gateOpen = ____; }`

### Room 3 – The storm (open sea)
- The team's ship sails to the captain's ship (about 15 s). The wind (`wind`, 0-9) changes every
  2-3 s in a fixed pattern (1, 5, 8, 2, 6, 9, ...), so every range comes up in the first 10 s.
- The sailor's table at the dock says "WIND 7-9: SAILS DOWN (0) / 3-6: HALF (1) / 0-2: FULL (2)".
  Turning a table of ranges into an else-if chain is the exercise.
- Each wrong setting fails in its own way and sends the ship back to the dock: sails up in a storm
  snap the mast, full sails at 3-6 rip, and too few sails stall the ship.
- The famous bug is `if (wind >= 3) { sails = 1; } else if (wind >= 7) { sails = 0; } ...`, which
  snaps the mast at wind 8. Byte: "The wind was 8. Java checks from the top: 8 >= 3 was already
  true, so it never reached wind >= 7. Put the biggest number first."
- Without the last else, nothing runs in a calm and the sails stay as they were. Byte says so.
- Pink Stars leap onto the deck, and there are coins in the rigging.

### Room 4 – The password (the captain's deck)
- A lookout in the crow's nest shouts a word every 3 s (`word`: "avast", "ahoy", "arrr",
  "yo-ho"). If the boarding gate is open on any word except "ahoy", the lookout fires the deck
  cannon down the gangplank, which knocks you into the sea (back to the checkpoint).
- `if (word.equals("ahoy")) { gateOpen = true; } else { gateOpen = false; }`
- `word == "ahoy"`: Byte explains that `==` checks whether it's the same String object, not the
  same letters, and puts `word.equals("ahoy")` in the input. This is like Level 1's
  redeclaration fix and isn't a wrong try.
- `word.equals("Ahoy")` never opens: "equals checks every letter, capitals too." Without an else,
  the gate stays open after "ahoy" and the cannon fires at the next word.
- The manual also shows that chars are compared with `==` (`'A' == 'A'`), since they aren't objects.
- Fierce Tooth guards patrol the deck (use the sword). Kervin sprints across a falling gangplank.

### Room 5 – The sleeping crew (the hold)
- The crew sleeps in the hold and wakes for about 3 s every 6 s (`awake`). If the lanterns are
  lit while they're awake, they spot you and charge. In the dark you only see what's near
  Byte's glow, and the spikes are hard to spot.
- `if (awake) { lightsOn = false; } else { lightsOn = true; }`
- `if (awake == true)` works too, and Byte adds: "awake is already true or false, so if (awake)
  says the same."
- `if (awake = true)`: Byte says "= stores true in awake, so this if is always true. Compare with
  ==, or just write if (awake)." (Java compiles this one, which is why it's such a common bug.)
- Sarah dashes over the bilge trench in the dark.

### Room 6 – The captain's bugs (final exam, the cove and the treasure cave)
About 3 x 2 screens with six sections, like Level 1's exam. Every machine already runs one of
the captain's rules (shown on the rule panel). Opening the terminal in a section puts the
captain's rule in the input, ready to edit. The first five sections are bugs to find:

| Section | The captain's rule | What goes wrong | Fix |
|---|---|---|---|
| 1 The stuck gate | `if (tide = 0) { gateOpen = true; } else { gateOpen = false; }` | it can't run (= stores, it can't compare), so the gate stays shut | `tide == 0` |
| 2 The runaway boat | `if (tide >= 4); { anchorUp = true; }` | the `;` ends the if, so the anchor comes up at any tide. The panel shows **false**, but the block runs anyway | remove the `;` |
| 3 The backwards sails | `if (wind >= 3) { sails = 1; } else if (wind >= 7) { sails = 0; } else { sails = 2; }` | the storm branch can never run, so the mast snaps | biggest number first |
| 4 The vault | `if (word.equals("Treasure")) { gateOpen = true; } else { gateOpen = false; }` | the lookout shouts "treasure" in lowercase, so it never opens | `"treasure"` |
| 5 The dark cave | `if (awake) { lightsOn = false; }` | the lights never come back on | add `else { lightsOn = true; }` |

**Section 6 – Captain Clown Nose (boss).** The captain guards the treasure in the cave's
arena. The captain's own rule is on the rule panel, so players can read what's coming:

```java
if (distance > 6) { move = 'C'; }        // charge
else if (distance > 2) { move = 'T'; }   // throw the sword
else { move = 'S'; }                     // swing
```

- Before each attack the captain shouts it and the reading `move` (char) becomes `'C'`, `'T'` or
  `'S'` about a second before it lands. Each attack has one counter:
  - `'C'` charge, sword raised high: only April's double jump clears it.
  - `'T'` the sword spins across the arena at head height and comes back: tiny Psalm (hold Down)
    is the only one it misses.
  - `'S'` a wide swing up close: Sarah's dash gets behind the captain before the blade lands.
- Byte hides when the fight starts (the captain swats at Byte), so there's no terminal in the
  arena. At the last checkpoint, the player leaves Byte a rule that picks the hero for each move:

  ```java
  if (move == 'C') { hero = "April"; } else if (move == 'T') { hero = "Psalm"; } else { hero = "Sarah"; }
  ```
- After each attack the captain is open for a moment (dizzy after the charge, empty-handed after
  the throw, off balance after the swing): hit him with the sword. Six hits win. At half health
  the captain "fixes" the rule (`distance > 4` for the charge), so the attacks come faster.
- A wrong rule loses the fight: back to the checkpoint, fix the rule with Byte, try again.
- After the fight: the treasure chest, the big map unfolds, level complete.

## Byte's terminal: what's new
The input stays one line, and accepted rules are shown on several lines in the rule panel.
The checker learns one new statement:

```
if (<condition>) { <statements> }  [else if (<condition>) { <statements> }]...  [else { <statements> }]
```

- **condition**: `name op value` (or `value op name`), a boolean on its own (`awake`), or
  `name.equals("text")`. `op` is one of `==` `!=` `<` `>` `<=` `>=`. Numbers can use any of
  them, chars and booleans use `==` and `!=`, and Strings use `.equals`.
- **statements**: assignments (Level 1's checks, reused) and `System.out.println(...)`, one or
  more, each ending in `;`.
- Byte's checklist for a rule: `if` spelled right -> condition in `( )` -> no `;` after `)` ->
  the condition's name, operator and value fit together -> `{ }` there and matching -> each
  statement inside is OK -> each `else` / `else if` part is OK -> the rule checks a reading and
  only sets this room's machines -> **Rule saved!**

| Mistake | Byte says |
|---|---|
| `If (tide > 3)` | Java is case-sensitive: write if in lowercase. |
| `if tide > 3 { ... }` | Put the condition in brackets: if (tide > 3) |
| `if (tide = 3)` | One = stores a value. To compare, use ==. |
| `if (tide => 3)`, `=<` | The = goes last: >= and <=. |
| `if (tide > "3")` | tide is a number, so compare it with a number - no quotes. |
| `if (word == "ahoy")` | Strings are compared with .equals: word.equals("ahoy") (Byte fixes it). |
| `if (move == "C")` | move is a char: use single quotes, 'C'. |
| `if (tide > 3); { ... }` | Remove the ; - it ends the if, so the code in { } would always run. |
| `if (tide > 3) gateOpen = false;` | Put the code the if runs inside { }. |
| `{ gateOpen = false }` | Every statement inside { } ends with ;. |
| `else (tide < 3) { ... }` | else has no condition. To check another one, use else if (...). |
| `elseif`, `else If` | else if is two words, both lowercase. |
| `if (true)`, `if (5 > 3)` | That's always true, so it doesn't decide anything. Check a reading, like tide. |
| `tide = 5;` | You can't change the tide! You can only check it. |
| `gateOpen = true;` (no if) | This gate runs by itself - give it a rule (Byte fills in the if; not a wrong try). |
| `{ boolean gateOpen = true; }` | gateOpen belongs to the gate - leave out the type. |

- `&&`, `||` and `!` get "That's coming in Level 3! Here, one condition per if (and else for 'not')."
- **On purpose, these differ from real Java:** braces are required (Java lets you skip them for one
  line, which causes bugs); conditions that never change are refused; `==` on Strings and
  `if (x = true)` are refused with an explanation instead of running as the bugs they are.
  Expressions after `=` (`gateOpen = tide < 3;`) still aren't supported. Byte says "Use an if
  for now."

## The rule runner
- Each room (each section in the exam) holds one rule. It runs when the rule is typed and again
  whenever a reading in its condition changes. It runs the first branch whose condition is true
  and hands each assignment to that room's machines. They can be `CodeGadget`s like Level 1's,
  but rule values skip `CodeGadget`'s "is the player in my room?" check, so machines keep working
  after you leave.
- Readings register with the terminal, so `System.out.println(tide);` prints the live value.
- When a machine fails, it reports the values and the branch that ran. Byte explains, and it
  counts as a wrong try (`CodeTerminal.report_wrong`).
- Honest note for the manuscript: a rule is an `if` inside the machine's update loop. The panel
  says "runs every time the tide changes", and Level 4 (loops) can point back at it.

## Scale: 32 px tiles at full size
- The Treasure Hunters tiles are 32 x 32. The recommendation is to draw them at full size, as
  `assets/README.md` planned. The heroes are about as tall as the pack's own captain, and halving
  the tiles would throw away half the art's pixels.
- One screen is then 20 x 11 tiles (640 x 360), and rooms are 1-3 screens. The heroes' moves stay
  the same in pixels, so in tiles a normal jump climbs 1 tile and crosses up to 3. That makes a
  3-tile gap a hard jump, not a wall. April's double jump climbs about 3, and a jump plus Sarah's
  air dash, or Kervin's sprint jump, crosses about 5. As in Level 1, a low crawlspace is what
  stops jumping past a hero-only gap.
- Psalm's low gaps are half a tile (16 px), so they're built from props (a barrel shelf, a low
  beam), not tiles.
- Build the map with a new `tools/build_level2.gd`: text maps like Level 1's (one character per
  32 px tile) and a TileSet for each of the four tile sheets.
